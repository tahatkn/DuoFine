Consent Mode v2 on a static site, without a consent platform

Google Analytics stays off until someone says yes, the banner never becomes the largest thing on the screen, and the whole thing is about forty lines of JavaScript with no third party in the loop.

This site is a handful of static HTML files on GitHub Pages behind Cloudflare. It uses Google Analytics 4. It also has visitors in the EU, which means analytics cookies need consent, and Google's own rules for EEA traffic mean the consent has to be signalled to Google in the format it expects — Consent Mode v2.

The usual answer is a consent-management platform: a script tag, a hosted banner, a vendor list. On a site whose whole homepage weighs about sixty kilobytes, adding a hundred-kilobyte banner from a third party is a strange trade. So this is what we do instead. It is not legal advice; it is the engineering.

What Consent Mode v2 actually requires

Stripped of marketing, Consent Mode is a small contract between your page and gtag.js:

  • Before Google's tag runs, you push a default consent state onto dataLayer with four signals — ad_storage, ad_user_data, ad_personalization and analytics_storage — each granted or denied.
  • When the visitor decides, you push an update.

Google's tag then adjusts what it stores and sends. In "advanced" mode, the tag still loads and sends cookieless pings while consent is denied. We do not want even that, so we go one step further: the tag is not on the page at all until consent is granted.

Step 1: deny everything before anything loads

The first thing our site script does — before any element is touched — is declare the default. Everything is denied except the two signals that describe the site's own functioning:

JavaScript · script.js
window.dataLayer = window.dataLayer || [];
function gtag() { window.dataLayer.push(arguments); }

gtag("consent", "default", {
  ad_storage: "denied",
  ad_user_data: "denied",
  ad_personalization: "denied",
  analytics_storage: "denied",
  functionality_storage: "granted",
  security_storage: "granted",
  wait_for_update: 500
});

The gtag function is just a push onto an array. That is the whole trick: gtag.js, whenever it eventually loads, replays the array in order, so the default is always seen before anything else.

Step 2: load gtag.js only after consent

The choice is stored in localStorage under a versioned key. Bumping the key (we are on df_consent_v2) re-asks everyone, which is exactly what you want when the policy text changes.

JavaScript · script.js
var gaLoaded = false;
function loadAnalytics() {
  if (gaLoaded) return;
  gaLoaded = true;
  gtag("js", new Date());
  gtag("config", GA_ID, { anonymize_ip: true });
  var s = document.createElement("script");
  s.async = true;
  s.src = "https://www.googletagmanager.com/gtag/js?id=" + GA_ID;
  document.head.appendChild(s);
}

function grantConsent() {
  gtag("consent", "update", { analytics_storage: "granted" });
  loadAnalytics();
}

Returning visitors who accepted get analytics immediately, with no banner. Visitors who rejected get nothing, with no banner. Only the undecided see the panel. And until "Accept" is pressed, there is no request to any Google domain — you can verify it in the network tab, which is a nicer thing to be able to say to an auditor than "the pings are cookieless".

One more detail that matters in 2026: pages can be prerendered by the browser before anyone looks at them. Consent must not be asked, and analytics must not fire, for a page nobody has opened yet. So the consent module waits for document.prerendering to flip:

JavaScript · script.js
if (document.prerendering) {
  document.addEventListener("prerenderingchange", initConsent, { once: true });
} else {
  initConsent();
}

Step 3: a banner that is not the LCP element

Our first version of the banner slid in 1.2 seconds after load. On a phone it covered about a quarter of the viewport, and in one Lighthouse run it was selected as the Largest Contentful Paint element — the biggest thing to appear on the screen was the cookie notice. That is a bad first impression and a worse metric.

The fix is timing, not styling. The panel opens after the page has fully loaded and the visitor has done something — scrolled, tapped, pressed a key — or after four seconds, whichever comes first. By then the real content has painted and been measured.

JavaScript · script.js
function arm() {
  var t = setTimeout(open, 4000);
  var once = function () { clearTimeout(t); open(); };
  window.addEventListener("scroll", once, { once: true, passive: true });
  document.addEventListener("pointerdown", once, { once: true });
  document.addEventListener("keydown", once, { once: true });
}
if (document.readyState === "complete") arm();
else window.addEventListener("load", arm, { once: true });

Two smaller rules we follow: "Reject" and "Accept" are the same size and weight, and the panel is a single-line bar rather than a card. A choice that is visually rigged is not a choice, and regulators have started saying so.

Step 4: the CSP allowances

Because the tag is injected at runtime, the page's Content-Security-Policy has to allow it explicitly. Three lines are involved:

  • script-src … https://www.googletagmanager.com — for gtag.js and the scripts it chains.
  • connect-src … https://*.google-analytics.com https://*.analytics.google.com https://www.googletagmanager.com — for the collect requests, which go to regional hosts.
  • img-src … https://*.google-analytics.com — the fallback pixel some browsers use.

Nothing needs 'unsafe-inline'; the CSP note covers how we got rid of that too.

What you give up

  • No modelled data. Because the tag is absent until consent, Google cannot model the behaviour of people who declined. For a studio site that only wants to know which pages are read, that is fine. For an ad-driven business it might not be.
  • You own the banner. Its copy, its accessibility (role="region", a label, keyboard-reachable buttons) and its translations are yours to maintain. Ours is in English and Turkish.
  • You own the record. A consent platform logs consents for you. Here the only record is the visitor's localStorage. Whether that is enough depends on what you are being asked to prove; ask someone who can answer that.
Total cost: forty-odd lines in a file that was already there, zero kilobytes from third parties until consent, and a banner that shows up after the page rather than instead of it.
